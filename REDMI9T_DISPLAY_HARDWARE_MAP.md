# Redmi 9T NFC lemon — электрическая карта дисплея

**Состояние допуска — Stage C/B NO-GO.** Ни один вывод из карты не используется как указание для подключения пробника к конкретному контакту до сверки платы. В этом цикле использованы архивы и ПК.

**Уровни доказательств.** «Экземпляр» означает чтение устройства в сохранённом журнале. «DT» означает программное описание из оригинального boot/DTBO, сверенное с TWRP FDT. «Схема» означает данные проекта J19S с ещё не подтверждённой применимостью к конкретной ревизии. «Не установлено» означает отсутствие достаточного подтверждения.

## REFGEN

1. В оригинальном merged DT и TWRP FDT consumer с именем `refgen` расположен в core supply list **DSI Host**, ограничения и нагрузки нулевые. Скрипт проверил отсутствие `refgen-supply` во всех узлах обоих деревьев. Qualcomm Bengal DTS содержит ту же запись. Архивный TWRP сообщает dummy у host. Сообщение dummy `gdsc` у PHY — другой ресурс. [Сверка](logs/display-safety-gate/evidence.json) · [Qualcomm Bengal DSI](https://android.googlesource.com/kernel/msm-extra/devicetree/+/refs/heads/android-msm-redbull-4.19-android12/qcom/bengal-sde.dtsi) · [TWRP](logs/v8-authorized/twrp-dmesg-before.txt#L855)
2. У mainline есть binding `refgen-supply` для host, а в проверенном списке REFGEN providers нет SM6115. Родственные SoC используют разные register layouts. `PMI_REF_BYP` в схеме — отдельный названный вывод PMIC, доказанной связи с DSI REFGEN нет. Отдельные цепи L18 и S5/VDD_MX также не доказывают эту связь. [Bindings](logs/display-safety-gate/bindings-review.txt) · [Mainline REFGEN](https://github.com/torvalds/linux/blob/master/drivers/regulator/qcom-refgen-regulator.c) · [Схема](https://www.scribd.com/document/613010966/Xiaomi-Redmi-9T-Schematic-pcb)
3. **Реальный владелец не установлен.** Допустимое доказательство — документация именно Bengal/SM6115 с ресурсом и порядком управления, либо воспроизводимая трасса подтверждённого firmware handoff от cold boot до штатного off. Для внутреннего блока измерять произвольные платы или регистры по аналогии нельзя. Подготовленный guard отказывает в probe без provider, но сам provider не реализует. [Guard](display-v8/sm6115-refgen-required.patch)

## Что доступно без включения панели

- На ПК — повторная сверка исходных образов, DT, archival traces, исходников regulator/PHY, версий схемы и сборочных файлов. [Воспроизводимый аудит](scripts/audit-display-hardware.py)
- На обесточенной плате — маркировка PCB и flex, U2732 и варианты монтажа, положение pin 1, сверка net names и безопасных измерительных точек с подлинным графическим листом/boardview. Текстовое представление схемы смешивает столбцы CN2701 и не годится для назначения контактов.
- Если потребуется новый read-only снимок v8b — свойства DT и driver symlinks, уже сохранённый dmesg и программные счётчики без runtime resume. Clock/regulator summary может выполнять driver callbacks; использовать только заранее проверенные поля. [Stage C/A](V8_STAGE_C_A_RESULTS.md)
