# Labwc на Redmi 9T v8b — аппаратное испытание

## Один запуск после восстановления GPU и SSH

Архив передан по SFTP в tmpfs, SHA-256 совпал. Labwc 0.20.0 запущен один раз с headless GLES2. wlroots открыл `renderD128`, сообщил EGL 1.5, Mesa Project, драйвер `msm` и **GL renderer FD610**. GBM выделил буфер 480×720, GLES2 создал FBO, Labwc запустил Wayland-сокет и отобразил одно окно foot. В dmesg появилась запись об успешной загрузке `a630_sqe.fw`. Программного рендерера в журнале нет.

| Проверка | Результат |
|---|---|
| Labwc и аппаратный GL | Headless-выход 480×720 при 30 Гц создан на FD610 |
| Терминал | Одно окно foot отображено по журналу Labwc |
| Waybar | Завершился при релокации символов `libpulse.so.0`. Часы не подтверждены |
| wayvnc | Выбрал HEADLESS-1 и открыл приватный Unix-сокет. При выходе Waybar скрипт остановил сессию до подключения Windows |
| Ввод, меню, два окна, кадр | Не проверены. Скриншота с телефона нет |
| FPS VNC, задержка, CPU, RAM | Не измерены. 30 Гц относится к виртуальному выходу |

В исходнике `session.sh` добавлен каталог комплектных приватных библиотек PulseAudio к локальному `LD_LIBRARY_PATH`. ELF у `libpulse.so.0` задаёт абсолютный RUNPATH `/usr/lib/pulseaudio`, тогда как пакет распакован в `/tmp`. Офлайн-запуск ARM64 musl loader через QEMU подтвердил выбор комплектного `libpulsecommon-17.0.so` без ошибок релокации. Испытанный архив сохранён с исходным хешем. Перед следующим запуском нужно перепаковать исправленный скрипт и проверить Waybar с распаковкой вне системного дерева. foot также выдал предупреждение о недоступной таблице Compose для `C.UTF-8`. Xwayland в штатном системном пути отсутствует, что не помешало запуску нативного окна foot.

После выхода не осталось процессов пакета или сокетов сессии. Временные каталог пакета и `/dev/shm` удалены. SSH, NCM, COM4 и OpenRC работают, GPU вернулся в `suspended`, MDSS остался заблокирован. DISPCC и DSI без привязок, подсветка не появилась. Новых GPU/IOMMU faults нет. Счётчики всех шести LUN совпали, дисковых mounts и swap нет. Телефон остался на v8b. Stage C/B остаётся NO-GO.

Основные журналы находятся в `logs/v8b-labwc-hardware/`: `labwc.log.txt`, `waybar.log.txt`, `wayvnc.log.txt`, `waybar-offline-link.txt`, `session-dmesg-delta.txt` и снимки `session-*-com4.txt`.

## Предыдущая попытка, остановленная до запуска

**90-секундная сессия не началась.** COM4 подтвердил Linux 7.4.0-rc1-lemon-bringup-v8b, Alpine 3.24.4 и запущенные службы OpenRC lemon-net, lemon-sshd и lemon-health. Телефон продолжил работать на v8b.

| Проверка | Результат |
|---|---|
| COM4 | Ответил до и после предварительной проверки |
| DRM и GPU | В `/dev/dri` только `card0`. `renderD128` и `/sys/module/msm` отсутствуют. Runtime PM Adreno недоступен через render node |
| Изоляция дисплея | MDSS без привязки, `driver_override` равен `(null)`. Удерживающий override в текущей загрузке не установлен. Устройства DSI Host/PHY, модуль DISPCC, устройства на MIPI DSI и класс подсветки отсутствуют. Состояние физического питания LCDB не измерялось |
| RAM | В `/tmp` свободно 1 851 112 KiB, `MemAvailable` 3 516 688 KiB. `/dev` на devtmpfs, каталог `/dev/shm` отсутствует |
| USB NCM и SSH | Windows видит UsbNcm.sys и интерфейс USB VID 1D6B / PID 0106 / MI 02. Linux usb0 поднят с 192.168.77.2/30. Windows имеет 169.254.119.71/16, адрес 192.168.77.1/30 отсутствует. Ping завершился таймаутом. Восстановление адреса получило Windows System Error 5. Ручной вызов скрипта также остановила политика выполнения PowerShell. SSH не проверен |
| UFS | Шесть LUN. При исходной проверке отсутствовали дисковые mounts и swap. Счётчики sda–sdf, включая число операций и секторов записи, совпали в двух снимках |
| Labwc, Waybar, foot и wayvnc | Аппаратный запуск не выполнялся. Скриншот телефона, GL renderer, FPS, задержки, CPU и RSS отсутствуют. Офлайн-результаты приведены в [V8_LABWC_DESKTOP.md](V8_LABWC_DESKTOP.md) |

Архив на телефон не передавался. Каталоги `/tmp/lemon-labwc-v8b` и `/dev/shm` после проверки отсутствовали. Прошивка, перезагрузка, загрузка MSM и изменение состояния дисплейного тракта не выполнялись. Stage C/B остаётся NO-GO. К подготовке нового DE пока не приступали.

Логи в `logs/v8b-labwc-hardware/`: `com4-before.txt`, `com4-after.txt`, `windows-ip-final.txt`. Для следующей попытки нужны адрес Windows на подтверждённом USB NCM и отдельное разрешение на повторение штатной процедуры GPU-only: подтвердить, что MDSS не привязан, установить временный блокирующий override, однократно загрузить штатный MSM с `separate_gpu_kms=1` и повторно проверить изоляцию дисплея перед Labwc.
