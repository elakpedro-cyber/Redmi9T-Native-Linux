# GNOME Shell 50.3 и Mutter 50.2 — аппаратный тест FD610

## Фактический результат

Единственная попытка остановилась до запуска GNOME Shell. ARM64 watchdog создал приватное пространство PID и установил лимит 60 секунд. На первом шаге подготовки mount namespace команда BusyBox `mount -o rprivate /` завершилась с ошибкой `mount: can't find / in /etc/fstab`. Watchdog зафиксировал выход с кодом 1. EGL/GBM на телефоне не запускались. Повторной попытки не было.

| Проверка | Результат |
|---|---|
| Комплект | ARM64 GNOME Shell 50.3 + пересобранный Mutter 50.2. Архив 343 841 162 байта. SHA-256 `39e9f04010e1bfb40cd1b93843f94cead071eaf649226cecca489649d4fa7133` |
| Запрет software fallback | Из распакованного комплекта под QEMU получен явный отказ `Required DRM render node /dev/dri/renderD128 unavailable; software fallback refused`. Программный renderer и GNOME Shell не стартовали |

RDP не запускался. Телефон остался на v8b. Stage C/B остаётся NO-GO.

## Исправление перед следующим тестом

Приватизацию mount namespace перенёс из BusyBox в прямой вызов `mount(2)` с `MS_REC | MS_PRIVATE` внутри дочернего процесса watchdog. ARM64 watchdog r2 собран статически и сохранён отдельно от испытанного бинарника. В WSL нативный watchdog с тем же исходником и эмулированный ARM64 BusyBox прошли bind устройства, read-only bind sysfs, mount proc и tmpfs, исчезновение mounts после выхода, остановку отсоединённого потомка по дедлайну и остановку при EOF. Исправление на телефоне ещё не проверено. Контроллер теперь возвращает ошибку, если запуск не подтвердил FD610, готовность Shell или завершение по watchdog.

Следующий этап — с отдельного разрешения повторить ограниченный GPU-only запуск с watchdog r2. Подтвердить FD610 и измерить время запуска и пиковый PSS. Интерактивный доступ имеет смысл проверять отдельным этапом после стабильного GPU-only запуска.

## Допуск

Сборка из upstream Mutter 50.2 с тремя штатными патчами Alpine v3.24 и локальным `require-render-node.patch`. Архив исходников и штатные патчи сверены по SHA-512 из APKBUILD. Патч в headless-режиме требует конкретный render node, аппаратный GBM и строку GLES `GL_RENDERER` FD610. При отсутствии узла Mutter возвращает ошибку до создания surfaceless renderer. При отказе EGL, неподходящем рендерере или устройстве рабочая сессия не допускается.

Независимый watchdog использует монотонный таймер и собственные пространства PID, mount и network. В проверке на ПК он завершил PID 1 и дочерний процесс, который создал отдельную сессию, сработал при EOF и при отсутствии heartbeat. ARM64-бинарник собран статически. Сетевой heartbeat идёт по существующему SSH с проверкой ключа сервера. RDP в тесте отсутствует. Для мониторинга предусмотрены PSS, MemAvailable, суммарные CPU ticks, GPU runtime PM, частота, загрузка при наличии счётчика, thermal zones, dmesg и проверка привязок дисплейного тракта.

Сборочные журналы, скрипты подготовки и телеметрия находятся в `logs/v8b-gnome50-fd610/`. План графической среды и предыдущие результаты приведены в [V8_GNOME50_PREPARATION.md](V8_GNOME50_PREPARATION.md).
