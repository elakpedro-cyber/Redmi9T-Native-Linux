# Redmi 9T NFC — подготовка физического дисплея и сенсора

**Решение — Stage C/B NO-GO.** Работающий v8b и проверенный GNOME 50 Desktop сохранены. В этой сессии телефон проверен по SSH чтением текущих привязок и счётчиков. DISPCC и MDSS не привязаны, override `lemon-stage-b-hold` сохранён, DSI Host/PHY и DPU отсутствуют, шина MIPI DSI пуста. Adreno привязан отдельно, renderD128 присутствует, swap отсутствует, записи в наблюдаемых счётчиках шести UFS LUN нулевые. ### REFGEN и PLL

Stock Bengal описывает `refgen` в таблице DSI host, с нулевыми constraints и без phandle. Ядро для SM6115 использует общий DSI v2.4 bulk consumer. Реальный supply проверяется у **DSI host**, а не PHY. PM6125 L18 — отдельный аналоговый VDDA 1,232 В. Ни stock DT, ни драйвер REFGEN mainline не доказывают, что SM6115 питается от PMIC, RPM/RPMh или оставленного включённым внутреннего блока. Для выбора нужны SM6115-специфичная карта регистров/питания и документированный владелец или подтверждение firmware handoff при холодном старте. [Bengal](https://android.googlesource.com/kernel/msm-extra/devicetree/+/refs/heads/android-msm-redbull-4.19-android12/qcom/bengal-sde.dtsi) · [Mainline REFGEN](https://github.com/torvalds/linux/blob/master/drivers/regulator/qcom-refgen-regulator.c) · [Исследование](V8_REFGEN_RESEARCH.md)

Патч для будущей отдельной сборки проверяет доступный `refgen-supply` и получает его через optional API без dummy **до** host probe и чтения версии через runtime PM. При отсутствии возвращает ошибку, при незарегистрированном провайдере передаёт ошибку regulator core, включая defer. Это барьер, реальный provider по-прежнему неизвестен. Патч не применяется в v8b. [Патч REFGEN](display-v8/sm6115-refgen-required.patch)

В 14-нм PLL драйвер проверяет LOCK bit 5 и READY bit 0 в `PLL_RESET_SM_READY_STATUS` при prepare. При timeout старый путь возвращал ошибку после записи PLL_START, а clock core не вызывает unprepare для неуспешного prepare. Патч сбрасывает PLL_START, делает readback и возвращает `-ETIMEDOUT`. ARM64 QEMU подтвердил rollback в модели MMIO. Статус, возвращаемый общим clock framework, не заменяет чтение LOCK/READY во время отдельно разрешённого link-теста. [Mainline PHY](https://github.com/torvalds/linux/blob/master/drivers/gpu/drm/msm/dsi/phy/dsi_phy_14nm.c) · [Патч PLL](display-v8/dsi-14nm-pll-rollback.patch)

### LCDB и TD4330

LCDB теперь проверяет SC при ожидании VREG_OK и перед каждым последующим шагом ramp. Проверка off включает чтение состояния pull-down. Suspend допускается только при подтверждённом управляющем off без consumers, resume перепроверяет off без включения. Потеря readback защёлкивает UNKNOWN. Нет автоматической попытки повторного enable. Порядок и задержки существующего experimental выключения не менялись. Успех readback не измеряет отрицательную шину или остаточный заряд. Снятие и повторная загрузка драйвера не являются процедурой восстановления. [Драйвер](display-v8/qcom-lcdb-regulator-lemon.c) · [Тесты](logs/v8-display-touch/lcdb.txt)

TD4330 transport после частичной передачи on/off защёлкивает `RESET_REQUIRED`. Для нового сеанса вызывающий код обязан отдельно подтвердить цикл питания и reset. Ни transport, ни его тесты не регистрируют MIPI DSI driver. В таблице перечислены все 79 пакетов с индексом и смещением в исходном свойстве. Стандартные DCS помечены по назначению. Семантика недокументированных vendor-регистров оставлена неизвестной. DCS `51 0f ff` передаёт ненулевое значение яркости в контроллер панели, поэтому внешний аппаратный HWEN требуется независимо удерживать низким на этапах до подсветки. [79 команд](logs/v8-display-touch/td4330-packets.tsv) · [Сверенные байты](reports/v8-panel-packets.json)

### Подсветка и touch

Mainline `leds-lm3692x` при probe получает GPIO в состоянии LOW, затем штатно вызывает enable, который может поднять supply и HWEN даже при нулевой начальной яркости. Review-патч откладывает прямой вызов enable из probe для LM36923 на lemon и прекращает brightness path при ошибке enable. GPIO acquisition остаётся аппаратной операцией. До допуска кандидат I²C и LED backlight остаются disabled, без default trigger. Отдельно ещё нужно подтвердить безопасное выключение при сбое I²C, в том числе действительное HWEN low, отсутствие LED current и состояние boost после ошибки. [Патч LM36923](display-v8/lm36923-defer-boost.patch)

Сохранённый stock DT связывает TD4330 с Novatek NVT SPI, GENI SPI `4a88000`, логический CS1, reset GPIO103 и IRQ GPIO93. Два архива TWRP подтверждают trim NT36672A, project ID 0x5940 и FW 5. Выбор и RAM-only загрузка firmware для будущего mainline probe остаются отдельной проверкой. [Карта](REDMI9T_DISPLAY_HARDWARE_MAP.md#идентичность-и-варианты). Mainline I²C-драйвер совпадает названием семейства, но использует другой transport. Подготовлены ARM64 декодер normal report и вывод полных кадров через input MT Type B. Проверяются checksum, границы, дубликаты, отпускания, watchdog/handshake и служебные события. Код не сбрасывает контроллер и не загружает firmware. Перед полноценным SPI probe нужны подтверждение IRQ polarity/CS pinctrl, firmware с доказанным RAM-only путём, питание touch и синхронизация suspend с общими LAB/IBB. Для libinput затем проверить прямой touchscreen, multitouch slots и соответствие краёв/углов ориентации панели. [Код](display-v8/novatek-lemon-frame.c) · [Xiaomi SPI](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/02ca1a919564a9b176a79cce09c40977f833e9ac/drivers/input/touchscreen/NT36672A/nt36xxx.c)

### DT, DRM и GNOME

Офлайн DTB оставляет выключенными DISPCC, MDSS, DPU, DSI Host/PHY, LCDB, LM36923 и backlight. Аудит разрешает взаимные graph phandles DPU↔DSI, PHY, четыре lane, clocks и GDSC/RPM, порядок byte/pixel parents и PM6125 L18. Он отклоняет активный DSI и перепутанные clock parents. Подтверждённых panel compatible и touch consumer в дереве нет. [DTB](logs/v8-display-touch/gnome-kms-review.dtb) · [DT schemas](logs/v8-display-touch/dt-schema.txt) · [Аудит clocks](logs/v8-display-touch/clock-dt-audit.txt)

Физический GNOME должен запускаться из активной seat-сессии OpenRC/elogind с KMS/input fd. Текущий строгий патч Mutter для FD610 предназначен для headless. Физическому режиму нужна отдельная проверка renderer и scanout, PRIME/DMA-BUF import и fences при раздельных DRM devices. Подготовлен verify-only скрипт `gdctl` для уже перечисленного DSI connector и его точного mode ID. Кандидат — native portrait без transform, scale 2. В offline проверен вызов verify-only и отказ для HDMI. Native KMS/elogind, реальные CRTC/plane и touch gestures в этом цикле не испытаны. После локального завершения сеанса USB ACM и сохранённый headless RDP остаются путями диагностики и возврата. [План KMS](V8_GNOME50_PHYSICAL_DISPLAY.md) · [Скрипт режима](userspace/gnome50-v8b/verify-physical-mode.sh)
