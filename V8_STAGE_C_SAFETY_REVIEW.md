# Stage C — оценка готовности

## Подтверждено

v8b остаётся контрольной версией. Сохранён [снимок с SHA](snapshots/v8b-hardware-validated/manifest.json), прошивка и ядро не заменялись. Последняя read-only проверка SSH подтвердила v8b, Alpine/OpenRC, UDC, render node и UFS без дисковых mounts/swap. Stage B отдельно подтверждает COM4, NCM, аппаратный рендер до DSI, host/PHY probe и захват DISPCC PLL0. [Свежий SSH](logs/v8-stage-c/v8b-baseline.txt) · [Stage B](V8_STAGE_B_RESULTS.md).

Новый DT fixture изолирован от сборки boot. В нём единственное отличие — отключённый LCDB с двумя выходами без потребителей. DPU disabled, DSI panel child отсутствует, backlight disabled, touchscreen не активирован. Офлайн объект TD4330 без probe и LCDB модуль не входят в рабочий initramfs. Для проверки DSI на телефоне выполнено только чтение диагностических данных по SSH.

## Открытые блокеры

| Блокер | Требуемое подтверждение |
|---|---|
| REFGEN | Источник данных SM6115 для реального provider или доказательство штатного firmware ownership. |
| LCDB | Безопасная передача владения, cold-start, fault injection частичных записей, отключение без повторного пуска после SC и проверенный разряд. |
| Link и reset | Физический LP11 до reset, отдельно подтверждённый захват DSI PHY PLL, согласование BLLP/EoT с MSM. |
| Подсветка | Точная модель, число каналов, начальный режим и безопасный минимум. Probe не должен сам зажигать LED. |
| KMS | Проверенный порядок bridge callbacks, сохранение COM/SSH при передаче SimpleDRM и контроль питания при любой ошибке. |

Гипотезы LM36923 и firmware-owned REFGEN остаются гипотезами. При текущих данных аппаратно допустимо согласовать только этап A из плана. Он состоит из чтения состояния без probe. Этапы B–G заблокированы своими предварительными условиями. v8c не упакован.

## Решение после Stage C/B preflight

**NO-GO для подачи питания.** Телефон продолжает отвечать по SSH на v8b. Сверены SHA-256 оригинала и контрольного снимка. Повторно прошли проверки disabled fixture и baseline v8b, а также тест TD4330 transport. Драйвер и образ не менялись. [Диагностика SSH](logs/v8-stage-c-b-preflight/v8b-read-only.txt) · [Сверка baseline](logs/v8-stage-c-b-preflight/baseline-validation.txt).

| Критерий | GO / NO-GO | Основание |
|---|---|---|
| REFGEN подтверждён | **NO-GO** | Stock TWRP также использует dummy. Адрес, compatible и владелец на SM6115 неизвестны. |
| LCDB корректен в программной модели | **GO для модели** | Семь групп тестов, общий gate и защёлка после ошибок проверены. |
| Ошибки реального драйвера закрыты | **NO-GO** | v2 игнорирует часть отказов. Программная модель ещё не перенесена в подтверждённый PMIC lifecycle. |
| Назначение bias-шин определено | **GO для схемы и DT** | PMI632 LDO/NCP и сети VSP/VSN совпали по источникам. Карта точек на NFC-экземпляре ещё не сверена. |
| Параметры и измерение bias | **NO-GO** | Нет пределов для точной ревизии панели, осциллограмм и подтверждённых контактов. |
| DSI PHY PLL и LP11 | **NO-GO** | Порядок действий описан, но без REFGEN и подтверждённого LP11 нет допуска к link-тесту. |
| Восстановление при потере USB/SSH | **GO для плана** | Проверенный образ v8b, аппаратный вход в TWRP, верификация boot readback и COM4 после восстановления. |
| Подсветка | **NO-GO для активации** | LM36923YFFR подтверждён в схеме J19S, установленный компонент NFC-экземпляра требует BOM или фото. |

## Следующее строго ограниченное испытание

До снятия блокеров допустим к отдельному согласованию только **пассивный осмотр специалистом**. Сверить ревизию платы, BOM/маркировку U2732, оригинальный графический лист, разъём и карту измерительных сетей. Телефон при таком осмотре должен быть обесточен, а сам осмотр планируется отдельным сеансом. Критерий завершения — документированная карта с двумя bias-сетями, reference, pin 1 и подтверждёнными пределами панели. При несовпадении ревизии или отсутствии карты остановиться. Подача питания в этот сеанс не входит.

После закрытия критических пунктов отдельный C/B ограничивается одним управляемым циклом проверенных regulator consumers с независимой регистрацией двух bias-шин и проверкой разряда. DSI PLL, DCS, reset, подсветка и сенсор остаются за пределами цикла. При timeout, SC, ошибке readback, неподтверждённом off или потере USB прекратить тест, не повторять enable, сохранить доступный журнал. Оператор восстанавливает безопасное питание по измерениям. Если нарушена загрузка, применяет отдельный согласованный откат v8b через TWRP только в boot. [План A–G и восстановление](V8_STAGE_C_FIRST_BOOT.md).

## Обновление после C-драйвера и headless сборки

| Критерий | Решение |
|---|---|
| LCDB state machine и обработка ошибок | **GO офлайн.** Исполняемый C-код собран для ARM64. Mock regmap прошёл 70 инъекций и 96 конкурентных случаев. |
| Реальные правила LCDB, REFGEN и bias | **NO-GO аппаратно.** До включения нужны верифицированный handoff, подтверждение rollback и разряда PMI632, доказательство REFGEN на SM6115 и точные пределы панели. |
| NFC PCB и подсветка | **NO-GO аппаратно.** Документ Xiaomi связывает layout моделей, но ревизия экземпляра, U2732 и точки измерения ещё не верифицированы. |
| Headless Wayland/Freedreno | **GO для запроса отдельного теста.** Runtime испытан на ПК. Будущий тест ограничен RAM, Weston headless и существующим render node. |
| Откат и контрольная v8b | **GO для плана.** Образ v8b сохранён с прежним SHA. При сбое headless остановить процессы, собрать COM/SSH и очистить RAM; путь TWRP предусмотрен для отдельного согласованного восстановления. |

Пассивная сверка платы остаётся следующим этапом ветки питания. Headless можно испытывать отдельно после согласования, без изменений LCDB, DSI, REFGEN, подсветки и сенсора. [Проверка платы](BOARD_VERIFICATION_GUIDE.md) · [Headless сценарий](V8_HEADLESS_GRAPHICS.md) · [LCDB](V8_LCDB_IMPLEMENTATION.md).
