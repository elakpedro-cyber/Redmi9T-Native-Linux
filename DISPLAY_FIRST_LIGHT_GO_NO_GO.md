# Redmi 9T NFC — допуск к первому кадру

**Решение: NO-GO для физического экрана и Stage C/B.** PASS относится только к указанному доказательству. Для конкретного аппаратного этапа все применимые критические пункты должны быть PASS и нужно отдельное разрешение владельца. UNKNOWN в цепи питания или штатного отключения блокирует активацию. Результат TWRP, значение управляющего регистра или чтение на обесточенной плате не заменяют осциллограмму штатного выключения.

## A. Обесточенная плата

Квалифицированный специалист фиксирует маркировки PCB и LCD/flex, вариант U2732, положение pin 1 и ориентацию CN2701. Сверяет доступные точки VSP, VSN, VDDIO, GND/reference, HWEN, LED_A и `PMI_DISP_HW_EN` по соответствующей схеме/boardview. При проверке цепей использовать подходящий безопасный режим прибора для обесточенной сборки и учитывать пути через полупроводники. Не подключать пробники по текстовой расшифровке схемы. Осмотр и проверка цепей не подтверждают поведение работающей LCDB. [Карта платы](BOARD_VERIFICATION_GUIDE.md)

## B. Контролируемые измерения с питанием

Отдельное согласование плана до любых действий. Специалист заранее утверждает схему interposer/пробников, пределы модуля, допустимый common-mode и процедуру аварийной остановки. Сначала нужен доказанный владелец REFGEN, а для внутреннего узла — подтверждённый способ наблюдения. На согласованном штатном пути получить независимые осциллограммы VSP и VSN одновременно с VDDIO, указать начальные уровни, знак, порядок, ramp, ripple, overshoot и время разряда до установленного порога. Зарегистрировать штатное выключение и заранее определённый безопасный отказ. Ошибка readback, SC, аномалия тока, потеря USB или неопределённый разряд останавливают текущий этап без retry. Номинальные значения из stock — ориентиры для сопоставления, электрические пределы задаёт документация точного модуля. [Подробный план сигналов](V8_DISPLAY_TOUCH_FIRST_LIGHT.md#измерения-и-критерии)

## Первый кадр и сохранение v8b

После закрытия ворот идти по отдельным этапам: проверенные rails → DSI PHY/PLL и LP11 → TD4330 reset/DCS с аппаратно погашенной подсветкой → подтверждённый atomic commit/page flip → отдельно минимальная подсветка → FD610 PRIME scanout и GNOME native. COM4 и SSH остаются резервом. Разрешение на один этап не распространяется на следующий. [План A–I](V8_DISPLAY_TOUCH_FIRST_LIGHT.md)

В этом задании используется только офлайн [DTB с отключёнными узлами](logs/display-safety-gate/gnome-kms-review.dtb), побайтово совпавший с ранее проверенным по схемам. Сохранены [патчи и результаты ARM64/QEMU](V8_DISPLAY_TOUCH_BRINGUP.md#офлайн-регрессия) и [verify-only профиль Mutter](userspace/gnome50-v8b/verify-physical-mode.sh). Проверенный native KMS/seat и физический scanout ещё не получены. Новый boot с активной панелью не создавался.

Сохранить оригинальные backup, рабочий `artifacts/boot-linux-test-v8b.img` (24 707 072 байта, SHA-256 `9ce181e8a6170ce8773a923f03dd10f5edb405d1990fa09b4f4bc12f2e59a610`) и оба RAM-only SquashFS. При будущей ошибке сначала остановить эксперимент через COM/SSH и подтвердить безопасное off; при неизвестном bias оператор прекращает работу до проверки. В TWRP только с отдельным разрешением: root ADB, сверка раздела boot, RAM staging, SHA до записи и SHA точного префикса после. Если префикс уже совпадает, запись не требуется. Не считать раннее автомонтирование TWRP безопасным для UFS. После восстановления сверить v8b, COM4, NCM, закреплённый SSH host key и контрольный headless GNOME.
