# GNOME Shell 50.3 и Mutter 50.2 на Redmi 9T — watchdog r2

## Результат

GNOME Shell запустился на физическом Redmi 9T NFC под v8b и оставался доступен до 60-секундного дедлайна. Mutter 50.2 использовал аппаратный EGL/GBM на Adreno FD610 через `/dev/dri/renderD128`. DRM-драйвер — `msm`. Mutter выбрал этот узел как основной, включил режим без modeset, создал виртуальный монитор Meta-0 размером 480×720 и сокет `wayland-0`. В журнале есть `GNOME Shell started`. Программный fallback не использовался. Физический дисплей, RDP и удалённый ввод не входили в испытание.

## Допуск и изоляция

- SHA-256 архива совпал с проверенным офлайн комплектом `39e9f04010e1bfb40cd1b93843f94cead071eaf649226cecca489649d4fa7133`. В офлайн-среде без render node тот же архив явно отказался от software fallback. После SFTP совпали хеши архива, watchdog r2 и скриптов.
- На телефоне отдельная проверка без запуска GNOME подтвердила приватное mount namespace, sysfs только для чтения, внутренние proc и tmpfs и доступ к существующему renderD128. Watchdog завершил namespace по тестовому 5-секундному дедлайну. Потомок, запущенный через setsid, успел создать стартовый маркер, но не пережил дедлайн. Основная таблица монтирований не содержала тестовых mounts ни после preflight, ни во время GNOME.
- Выполнен один запуск Shell. Watchdog на телефоне завершил сеанс по дедлайну с кодом 124. RDP не запускался.

Частота, видимая в снимках devfreq, составила 320 МГц. `gpu_busy_percent` недоступен.

## Предупреждения и восстановление

Минимальный прямой запуск Shell сообщил об отсутствии GDM, SessionManager, colord, Polkit и GeoClue. Также зарегистрированы предупреждение о pixbuf/icon cache и отказ запуска camera monitor. Shell дошёл до готовности. Функции рабочего стола, зависящие от этих служб, не проверялись.

После дедлайна процессов GNOME в тестовом rootfs и тестовых монтирований не осталось. Временный каталог удалён, GPU вернулся в `suspended`. SSH и COM4 отвечают, ping через USB NCM менее 1 мс. Счётчики всех шести UFS LUN совпали, дисковых mounts и swap нет. В dmesg не появилось новых сообщений, включая GPU/IOMMU faults. Телефон оставлен на v8b с блокировкой MDSS. Stage C/B остаётся NO-GO.

## Следующий этап

Затем отдельно согласовать испытание RDP в network namespace с доступом через SSH. Первые критерии интерактивного теста — настоящий кадр Mutter, Activities, запуск Console и Settings, ввод с Windows и сохранение аппаратного FD610.
